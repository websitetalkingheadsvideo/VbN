# Valley by Night — Character Agent

## Purpose
The **Character Agent** is a non-destructive automation layer that inspects character data, produces storyteller-friendly briefs, and raises continuity warnings without overwriting canonical sources. It is designed to interoperate with future agents (Boon, Influence, Rumor) that will share the same folder contract.

## 1. Inputs
- Characters table accessed via `includes/connect.php` only — **primary** source of truth (`SELECT id, character_name, player_name, chronicle, concept, clan, generation, sire, pc, status, camarilla_status, biography, appearance, notes, agentNotes, actingNotes, character_image, Coterie, Relationships, created_at, updated_at FROM characters WHERE chronicle = 'Valley by Night'`).
- `data/*.json` — optional staging cache when specific imports need offline analysis; never the authoritative store.
- `reference/Valley_by_Night_Chronicle_Summary.md` — concise chronicle overview for lore anchoring.
- `reference/Scenes/Character Teasers/Valley_by_Night_Cinematic_Intro_Guide.md` — tone guide for narrative blurbs.
- `reference/Valley_by_Night_Character_Art_Guide.json` — art direction metadata for optional image prompts.
- `includes/connect.php` — *only* approved gateway for MySQL lookups whenever character verification requires DB data. No CLI or Powershell access is permitted.

## 2. Outputs
- Markdown briefs stored under `agents/character_agent/reports/daily|weekly/` summarising sheet highlights for each new or updated character.
- Missing-field Markdown reports (only when `biography`, `appearance`, or `notes` are empty) saved alongside the character brief with clear remediation steps.
- Structured JSON alongside briefs capturing missing-field suggestions for downstream automation.
- Optional plot hooks attached to the weekly brief set when enabled in `config/settings.json`.
- Continuity warning payloads saved as JSON in `reports/continuity/` and referenced inside the admin UI logs.
- Aggregated “History of Phoenix (Character-Derived)” Markdown generated by the `city_history_from_characters` mode, combining `biography`, `notes`, and `agentNotes` across all Valley by Night characters, saved in `agents/character_agent/reports/`.

## 4. Agent Responsibilities
**MVP**
- Detect new or updated characters via `created_at` / `updated_at` deltas compared against a stored `last_run` timestamp (persisted in config/log table or JSON cache), using the canonical database query through `connect.php` and treating `data/Characters/` as optional staging only.
- Validate sheets against Valley by Night required fields (name, clan, concept, sire, appearance, biography).
- Generate per-character Markdown briefs using prompts and lore references.
- Emit Markdown and machine-readable missing-field suggestions when required keys are blank or placeholders.
- Append log entries to `logs/agent_activity.log` for every processed character (new or updated) noting brief generation, missing-field report creation, and timestamps.
- Write daily report bundles and append summary entries to `logs/agent_activity.log`.
- Provide a `city_history_from_characters` aggregation mode that compiles long-form history content from biographies/notes/agentNotes and stores it in `reports/`.
- Surface latest report metadata inside `/admin/agents.php` (read-only).

**Future**
- Chronicle-wide continuity analysis (relationships, locations, timeline checks).
- Automated plot hook generation weighted by clan/faction balance.
- Cross-agent messaging bus for Boon/Influence/Rumor coordination.
- Admin-triggered reruns with configurable scope.
- External trigger bridge (REST/CLI) while still routing DB access through `connect.php`.

## 5. Admin Integration
- `/admin/admin_panel.php` already links to `/admin/agents.php`; navigation remains unchanged.
- `/admin/agents.php` should display Character Agent status plus the timestamp of the latest generated brief.
- Reports are exposed read-only via `/agents/character_agent/reports/index.php`.
- Future enhancement: “Run Character Agent” button that queues processing without blocking the UI.
- All report links must be relative so staging and production share the same path structure.
